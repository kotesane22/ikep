# WORKFLOW — ポートフォリオを更新する

> **使う場面**：作品を足す／販売リンクを足す／文章を直す／連載を増やす
> **承認**：ローカル編集・作業ブランチへのpushは不要。**`main` へのマージ＝公開は🔒必須**

---

## 0. 鉄則

> **HTML は触らない。** 文章・リンク・作品は**すべて `data/*.json` 側にある。**
> 見た目は **`css/tokens.css` の変数だけ**で変える。
> これを破ると、JSON追記だけで更新できる設計が壊れる。

---

## ケース別の手順

### A. 作品を増やす → `data/works.json`

`items` に1件追記するだけ。

```jsonc
{
  "id": "…",                      // 一意。既存と被らせない
  "title": "…",
  "category": "ai-image|copy|content",
  "size": "lg|wide|tall",         // 省略で通常。誌面のサイズ差用
  "thumb": "assets/works/xxx.webp",
  "description": "…",
  "url": "",
  "date": "2026-06"               // date降順で自動整列
}
```

- 画像は `assets/works/` に置く。**WebP推奨**
- `size` は**全部に付けない**。付けすぎると「均一密度」になりNG（`USER_PROFILE.md` §7）
- **主役1点＋支持する複数点**のリズムを守る（`RESEARCH.md` §4）

### B. 販売リンクを増やす → `data/shop.json`

`items` に `{ "id", "name", "url" }` を1件追記。
**`url` が空だと「準備中」表示になり、リンクにならない。**

### C. 問い合わせ導線を設定する → `data/contact.json`

各 `items[].url` を埋める。**空のままだと「準備中」でリンクにならない。**
→ **現在7件中0件。最優先タスク T-002 / T-003。**

### D. プロフィールを直す → `data/profile.json`

`facts`（項目表）/ `lead`（`\n`で改行）/ `body`（段落配列）/ `note`（補足）/ `creds`（実績）。
※値にHTMLタグを書いても効かない（エスケープ済み・仕様）。

### E. 連載「今日の30秒」を増やす → `data/habits.json`

`items` に1件追記。**書けば書くほど周期が伸びる**（3件＝3日で一巡、30件＝30日で一巡）。

> ⚠️ **日替わりの決定性を壊さない。**
> ローカル日付の通日 % 件数 で1件を選ぶ実装（`js/habit.js`）。
> **`Math.random()` や `localStorage` を持ち込まない。**

### F. 見た目を変える → `css/tokens.css`

色・フォント・余白・角丸・影・モーションは**すべて変数**。
`style.css` に直書きの色や余白を**増やさない**。

## 更新後のチェック（毎回）

```bash
python3 -m http.server 8000   # file:// 直開きは fetch が失敗するので必須
# → http://localhost:8000/
```

- [ ] JSONが壊れていない（カンマ・括弧）
- [ ] 追加した項目が表示される
- [ ] **375px幅で横スクロールが出ない**（`scrollWidth === innerWidth`）
- [ ] JS無効でも本文が読める（`.reveal` の `.has-js` ガードを壊していない）
- [ ] 画像の縦横比・トーンが他と揃っている

## デザインのガードレール（`CLAUDE.md` と同じ・破らない）

- 紫グラデ／絵文字装飾／無意味な英語見出しの乱発
- 「羅針盤」「設計図」系のテンプレ比喩
- 全セクション均一密度（メリハリのない画面）
- ソシャゲ風テンプレ、ありがちなグラデーションヒーロー

> **余白で見せる。作品が主役、装飾は脇役。**
