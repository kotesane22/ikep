# WORKFLOW — note記事を書く

> **使う場面**：note記事を1本仕上げる時
> **所要**：60〜120分 ／ **承認**：投稿は🔒必須（下書きまでは承認不要）

## 使うスキル

- `/note-article-workflow` … 執筆 → タイトル10案 → AI臭チェックの3フェーズ
- `/note-with-image-workflow` … 挿絵・サムネイルもセットで作る場合
- `/matome-writer` … まとめ文（締めくくり）だけ欲しい場合

**基本は `/note-article-workflow` を呼ぶ。** この文書はその前後の運用を定める。

---

## 手順

### Phase 0 — 前提を揃える（ノアが確認する）
- [ ] テーマは決まっているか
- [ ] **誰に向けた文章か**を一言で言えるか（`data/habits.json` h002 と同じ原則）
- [ ] いけP自身の**体験・実感**が入っているか（ここが無いと「AI×人間味」が消える）
- [ ] 読者が読み終わって**何ができるようになるか**

> 4つのうち2つ以上が埋まらない → **書き始めない。** ヒアリングを先にやる。

### Phase 1 — 執筆
`/note-article-workflow` を実行。約5,000文字。

### Phase 2 — タイトル
10案 → いけPが選ぶ → 本文に反映。

### Phase 3 — AI臭チェック（**飛ばさない**）
`USER_PROFILE.md` §6 のNGを必ず通す：
- [ ] 無意味な英語見出しの乱発がない
- [ ] 絵文字装飾がない
- [ ] 「羅針盤」「設計図」系のテンプレ比喩がない
- [ ] のっぺりした均一な密度になっていない（＝「チャッピーっぽい」状態）
- [ ] 抽象論で終わらず「で、何をするか」まで書いてある
- [ ] いけPの体温が残っているか（**ここが最後の砦**）

### Phase 4 — 導線を仕込む
- [ ] ポートフォリオへのリンク（`https://kotesane22.github.io/ikep/`）
- [ ] 依頼導線（ココナラ／クラウドワークス）※T-002完了後
- [ ] X へのリンク

### Phase 5 — 提出（🔒 投稿は承認必須）
ノアは**下書きまで**。投稿はいけPが行うか、明示的な承認を得てから。

---

## 終わったら

- `TASKS.md` の該当タスクを ✅ に
- 反応がよかった表現を `LEARNINGS.md`「効いた表現・型のストック」へ
- 記事が実績になるなら `data/works.json` への追加を検討（→ `portfolio-update.md`）
