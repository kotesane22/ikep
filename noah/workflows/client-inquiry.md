# WORKFLOW — 問い合わせ〜納品までの案件対応

> **使う場面**：ココナラ・クラウドワークス・メールから依頼が来た時
> **承認**：🔒 **返信・見積・受注確定はすべて承認必須**

---

## 0. 大原則

> **ノアは下書きを作る。送信はしない。**
> 返信文・見積・提案書はすべて「コピペできる完成形」で提示し、送信はいけPが行う。

---

## Phase 1 — 受信（ノア：即対応）

1. 依頼内容を**3行に要約**する（何を／いつまでに／いくらで）
2. **不明点を洗い出す**。特に：
   - [ ] 納期
   - [ ] 予算
   - [ ] 用途（商用か／どこに出すか）
   - [ ] 修正回数の想定
   - [ ] 素材の提供有無
3. 受けるべき案件かを判定する

| 判定 | 基準 |
|---|---|
| ✅ 受ける | 北極星に寄与する／実績として掲載できる／時間が読める |
| ⚠️ 要相談 | 単価が読めない／範囲が曖昧／修正無制限の匂い |
| ❌ 見送り | 稼働を超える／ポジション（AI×人間味）とズレる／不明点に答えが来ない |

## Phase 2 — 初回返信（🔒承認必須）

ノアが下書きを作る。型：

```
① お礼＋読んだことを示す（相手の言葉を引く）
② こちらの理解の要約（認識合わせ）
③ 不明点の質問（3つまで。多いと返信が来ない）
④ 進め方とおおよその納期感
⑤ 次のアクションの提示
```

**必要に応じて `短縮版 / 丁寧版 / 熱量高め版` を添える。**

## Phase 3 — 見積・提案（🔒承認必須）

- [ ] 作業範囲を**明文化**する（「どこまでやるか」より「どこからは別料金か」）
- [ ] 修正回数を明記する（無制限にしない）
- [ ] 納期を明記する
- [ ] 実績掲載の可否を確認する（← **これを聞き忘れると資産にならない**）

## Phase 4 — 制作

- 該当する workflow を使う（`image-prompt.md` / `note-article.md` など）
- 中間報告を1回入れる。**完成してから見せない**（手戻りが最大化する）

## Phase 5 — 納品（🔒承認必須）

- [ ] 納品物の確認
- [ ] 使い方・注意点を添える
- [ ] **実績掲載の許可を改めて取る**

## Phase 6 — 資産化（ノア：承認不要の部分）

- [ ] `data/works.json` に追加（→ `portfolio-update.md`）※掲載許可がある場合のみ
- [ ] `LEARNINGS.md` に学びを1行
- [ ] 単価・所要時間の実績を記録（**金額は D-001 確定まで台帳に書かない**）

---

## 案件中の記録

- 案件は `PROJECTS.md` に **1件＝1プロジェクト**として立てる
- 締切は `TASKS.md` の P0 に入れる。**案件は常に最優先**
