# LEARNINGS — 学びと未達の記録

> 効いたこと・外したこと・続かなかった理由を貯める。**同じ失敗を二度しないための台帳。**
> 最終更新: 2026-09-03

## 書き方の型

```
### L-000 一行で言い切るタイトル
- 日付 / きっかけ
- 何が起きたか（事実だけ）
- なぜそうなったか（解釈）
- 次からどうするか（**行動に変換する。ここが本体**）
```

**書く基準**：次に活かせないものは書かない。感想文は貯めない。

## 運用から得た学び

### L-001 「あとで直す」と書かれた仮データは、自然には消えない
- **日付**：2026-09-03 ／ **きっかけ**：初回監査
- **何が起きたか**：サイトの実装は完成しているのに、works 7件・profile本文・habits 3件・
  contact 5件・shop 2件のすべてが仮のまま残っていた。`_note` に「差し替え予定」と書かれたまま。
- **なぜ**：**仮データは「動いてしまう」から、痛みが出ない。** 表示上は成立しているので、
  優先順位が上がらないまま次の実装に進んでしまう。
- **次から**：仮データを入れる時は、**同時に `TASKS.md` に差し替えタスクと期限を立てる。**
  「仮」と書いただけでは、それはタスクではなくメモ。

### L-002 指示書は、実装より簡単に古くなる
- **日付**：2026-09-03 ／ **きっかけ**：`CLAUDE.md` にv1.0とv2.0が併記されているのを発見
- **何が起きたか**：実装はv3（アイボリー紙×真鍮）まで進んでいたのに、
  指示書は「v2.0を優先」（オフブラック×アンバー）のまま。**2世代の乖離。**
- **なぜ**：実装は動かすたびに更新されるが、**指示書は誰も困らないので更新されない。**
  困るのは「次に読む人（AI）」で、その人はまだこの場にいない。
- **次から**：**デザインや方針を変えたコミットでは、必ず同じコミットで指示書も直す。**
  別コミットに回した時点で、直されない。

### L-003 器（構造）が良くても、中身が仮なら成果はゼロ
- **日付**：2026-09-03 ／ **きっかけ**：初回監査
- **何が起きたか**：JSON追記だけで更新できる構造・トークン一元管理・JS無効時のフォールバックまで
  設計された良い土台があるのに、**依頼を受け取る導線が7件中0件**だった。
- **なぜ**：**作るのは楽しく、埋めるのは地味。** 構造を作った時点で「進んだ感」が出てしまう。
- **次から**：プロジェクトの進捗は「実装率」でなく **「成果が発生し得る状態か」** で測る。
  → `PROJECTS.md` の進捗欄は、この基準で書く。

### L-004 同じ情報を2箇所に書いた時点で、矛盾は確定している
- **日付**：2026-09-03 ／ **きっかけ**：`README.md` と `HANDOFF.md` の重複を検出
- **何が起きたか**：ファイル構成表・更新手順がほぼ同じ内容で2箇所にあった。
  さらに両方が「モノレポ `apps/portfolio/`」前提で、**実体（`ikep` のルート）とズレていた。**
  README が案内する `scripts/sync-to-ikep.sh` は**このリポジトリに存在しない。**
- **なぜ**：親切心で書き写すと、更新のたびに片方が取り残される。
- **次から**：**単一出典の原則**（D-006）。書き写したくなったら、リンクにする。

**原因分類**：`①時間不足 / ②手順不明 / ③承認待ちで停止 / ④粒度が大きすぎた`

### 分類ごとの打ち手（週次で集計して判断する）

| 多い原因 | 打つ手 |
|---|---|
| ①時間不足が多い | 1日のP0を減らす。目標そのものを下げる判断も検討する |
| ②手順不明が多い | `workflows/` にその手順を書く。**次からは迷わない状態にする** |
| ③承認待ちが多い | 承認のまとめ方を変える（都度 → 週1バッチ、など） |
| ④粒度過大が多い | タスクの切り方を見直す。**「1回で終わる大きさ」まで割る** |
