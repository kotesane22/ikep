# APPROVALS — 承認ルールと承認待ち

> 「勝手にやっていいこと」と「承認が要ること」の**唯一の出典**。
> 最終更新: 2026-09-03

---

## 0. 大原則

> **明示的な承認なしに、投稿・送信・公開・購入・契約・削除・アカウント設定変更は行わない。**

判断に迷ったら、この2問で判定する：

```
Q1. これは外（他人の目・他人の受信箱・インターネット）に出るか？
Q2. 取り消せるか？ 取り消しに手間や損害が出ないか？
```

**Q1がYes、またはQ2がNo → 承認を取る。** 迷ったら承認側に倒す。

（GitHub Pages は `main` のみ配信するため）。ただし**リポジトリ自体が public であることは忘れない**。

## 2. 🔒 いけPの承認が必要なこと

| カテゴリ | 具体例 | 理由 |
|---|---|---|
| **公開** | GitHub Pages の有効化、`main` へのマージ、サイトの公開 | 取り消しても検索エンジンに残る |
| **投稿** | X・note・その他SNSへの投稿、引用RT | 外に出る・取り消せない |
| **送信** | メール、DM、問い合わせ返信、見積の送付 | 相手に届く |
| **購入・契約** | 有料サービスの契約、ドメイン取得、素材購入、案件の受注確定 | 金銭が動く |
| **削除** | ファイル・ブランチ・リポジトリ・データの削除 | 復旧できない場合がある |
| **設定変更** | GitHub・SNS・各種サービスのアカウント設定、権限変更 | 影響範囲が読めない |
| **公開文言の確定** | プロフィール本文、キャッチコピー、実績の記載内容 | 本人の言葉として世に出る |
| **機微情報の記載** | 金額・単価・個人連絡先を台帳に書くこと | 公開リポジトリのため（D-001が未確定の間） |

## 4. 承認のやり方

- **形式**：このチャットで「A-1はA」「A-3のnoteはこれ → URL」のように番号で返す。
- **粒度**：**1回の承認は1回きり有効。** 「前にOKしたから今回も」とはしない。
  継続的に許可する場合は「今後◯◯は承認不要」と明示的に言う → 本ファイルの §1 に追記する。
- **記録**：承認されたものは §5 の承認ログに残す。**口頭で終わらせない。**
- **【要確定】** 承認の通知手段（チャットのみ／それ以外）→ A-5 と併せて確認したい

## 6. ノアがやってはいけないこと（例外なし）

- 承認前に「どうせOKだろう」で外に出す
- 承認済みの範囲を**少しだけ**超える（「ついでに」は禁止）
- 承認が取れないことを理由に、**黙って止まる**
  → 止まる時は必ず「何を待っているか」を `TASKS.md` と本ファイルに書き、**待っている間にできる別のことを進める**
- 未達や失敗を報告しない／小さく見せる
